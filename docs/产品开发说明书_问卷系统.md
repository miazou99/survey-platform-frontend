**版本**：V1.0

**状态**：初稿，供内部研发参考

## 一、产品概述

### 1.1 产品定位

自主研发的问卷调研平台，支持 **合成数据 + 真人样本库** 双轨道运营模式。核心价值：

- 问卷创建、分发、数据收集（基础能力）
- 基于用户画像的精准抽样与配额管理
- 与微信生态深度集成（openid 传递、红包发放）
- 支持 Webhook 回调，实现业务自动化

### 1.2 核心业务流程

```
┌─────────────────────────────────────────────────────────────────┐
│                         完整业务流程                              │
└─────────────────────────────────────────────────────────────────┘

① 问卷创建与发布
   ├── 创建问卷（题目、逻辑、跳转）
   ├── 设置自定义参数（__OPENID__ 占位符）
   ├── 开启 Webhook 数据推送
   └── 生成问卷链接

② 用户抽样与推送
   ├── 配置项目配额（维度、标签、占比、目标数量）
   ├── 根据用户画像筛选符合配额的样本
   ├── 通过模板消息推送问卷链接（自动替换 openid）

③ 用户答题
   └── 用户点击链接 → openid 自动注入问卷

④ 数据回传与红包发放
   └── 用户提交答卷 → Webhook 推送数据 → 系统发放红包

⑤ 数据汇总与分析
   └── 按配额维度统计答卷分布 → 导出/分析
```

## 三、核心功能详细说明

### 3.1 问卷管理

#### 3.1.1 问卷创建

**功能点**：
- 多题型支持：单选、多选、填空、量表、矩阵、排序
- 题目逻辑：跳过逻辑、随机显示、条件分支
- 样式定制：logo、背景色、按钮文案

**技术要点**：
- 问卷模板可复用（创建副本）
- 题目 ID 全局唯一，支持外部引用

#### 3.1.2 自定义参数配置（关键功能）

**功能描述**：
在问卷链接中嵌入自定义参数，答题时自动携带。

**配置项**：
| 参数名 | 说明 | 示例 |
|--------|------|------|
| `__OPENID__` | 微信用户唯一标识（必填） | `__OPENID__` 自动替换为真实 openid |
| `__PROJECT_ID__` | 项目 ID | 用于关联项目 |
| `__CHANNEL__` | 渠道来源 | `wechat/template` |

**实现要求**：
- 在问卷平台后台开启「自定义参数」功能
- 生成链接时，将 `__OPENID__` 作为占位符
- 推送模板消息时，替换为真实 openid

#### 3.1.3 Webhook 配置

**功能描述**：
用户提交答卷后，问卷系统自动将数据 POST 到指定接口。

**配置项**：
| 字段 | 说明 |
|------|------|
| Webhook URL | 接收数据的接口地址 |
| 签名密钥 | 用于校验请求来源 |
| 推送时机 | 立即推送 / 每日汇总 |

**数据格式**（参考腾讯问卷商业版）：

```json
{
  "event": "survey.submit",
  "timestamp": 1743427200,
  "signature": "abc123...",
  "data": {
    "survey_id": "SURVEY_001",
    "submit_id": "SUB_123456",
    "custom_args": {
      "openid": "oXXXXXX",
      "project_id": "PROJ_001"
    },
    "answers": [
      {
        "question_id": "Q1",
        "question_type": "single",
        "answer": "A"
      }
    ],
    "submit_time": "2026-03-31 16:42:00"
  }
}
```

### 3.2 用户画像与配额管理

#### 3.2.1 用户画像维度（6个核心维度）

| 维度 | 英文 key | 可选标签示例 |
|------|----------|--------------|
| 性别 | `gender` | 男、女 |
| 年龄 | `age` | 18-24、25-34、35-44、45+ |
| 地区 | `region` | 一线城市、二线城市、三线城市 |
| 行业 | `industry` | 互联网、金融、制造业、零售... |
| 职业 | `occupation` | 白领、公务员、学生、自由职业... |
| 收入 | `income` | 5k以下、5k-10k、10k-20k、20k+ |

**数据结构**：

```typescript
// 用户画像
interface UserProfile {
  openid: string;          // 微信 openid（唯一标识）
  gender?: string;         // 性别
  age?: string;             // 年龄段
  region?: string;          // 地区
  industry?: string;        // 行业
  occupation?: string;      // 职业
  income?: string;          // 收入
  created_at: string;       // 入库时间
  tags?: string[];          // 自定义标签
}

// 配额项
interface QuotaItem {
  dimension_key: string;    // 如 'gender'
  dimension_label: string;  // 如 '性别'
  tag_name: string;         // 如 '男'
  quota_percent: number;    // 如 50（占比%）
  target_count: number;     // 如 500（目标数量）
}

// 项目配额
interface ProjectQuota {
  total_samples: number;           // 目标投放总量
  selected_dimensions: string[];   // 选择的维度列表
  quotas: QuotaItem[];             // 各维度配额详情
}
```

#### 3.2.2 配额配置页面交互

**操作流程**：
1. 选择维度（如勾选「性别」「年龄」）
2. 每个维度下配置标签占比
3. 系统自动计算目标数量（基于总量 × 占比）
4. 支持手动调整目标数量

**前端展示**：

```
项目配额情况
├── 目标投放总量：10,000
├── 已选维度：性别、年龄段、地区
│
├── 性别
│   ├── 男（50%）→ 目标 5,000
│   └── 女（50%）→ 目标 5,000
│
├── 年龄段
│   ├── 18-24（20%）→ 目标 2,000
│   ├── 25-34（35%）→ 目标 3,500
│   └── 35-44（30%）→ 目标 3,000
│
└── 地区
    ├── 一线城市（40%）→ 目标 4,000
    └── 二线城市（60%）→ 目标 6,000
```

### 3.3 Webhook 数据处理

#### 3.3.1 Webhook 接收接口

**接口规格**：

```
POST /api/webhook/survey
Content-Type: application/json
X-Signature: {signature}
```

**处理流程**：

```
1. 接收 POST 请求
2. 验证签名（防伪造）
3. 解析 body 获取 openid、project_id、answers
4. 根据 openid 查询用户画像
5. 根据 project_id 查询项目配额
6. 判断用户是否符合配额条件
7. 如符合：触发红包发放
8. 写入答卷记录
9. 更新配额进度
10. 返回 200 OK
```

#### 3.3.2 红包发放流程

**前置条件**：
- 微信支付商户号已开通
- 账户已通过 90天+30天 正常交易审核

**发放方式**：
- 使用微信支付「现金红包」接口
- 通过 `openid` 发放到用户微信钱包

**接口调用**（参考微信支付文档）：

```
POST https://api.mch.weixin.qq.com/mmpaymkttransfers/sendredpack
{
  "nonce_str": "随机字符串",
  "sign": "签名",
  "mch_billno": "商户订单号",
  "mch_id": "商户号",
  "wxappid": "小程序AppID",
  "send_name": "发红包主体名称",
  "re_openid": "用户openid",
  "total_amount": 100,  // 最小100分=1元
  "total_num": 1,
  "wishing": "感谢您参与调研！",
  "act_name": "问卷调研红包",
  "remark": "答题红包奖励"
}
```

## 四、数据库设计建议

### 4.1 核心表结构

```sql
-- 用户画像表
CREATE TABLE user_profiles (
  id SERIAL PRIMARY KEY,
  openid VARCHAR(64) UNIQUE NOT NULL,    -- 微信openid
  gender VARCHAR(10),                     -- 性别
  age_range VARCHAR(20),                 -- 年龄段
  region VARCHAR(50),                    -- 地区
  industry VARCHAR(50),                  -- 行业
  occupation VARCHAR(50),                -- 职业
  income_range VARCHAR(30),               -- 收入
  tags JSONB,                             -- 自定义标签
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

-- 项目表
CREATE TABLE projects (
  id SERIAL PRIMARY KEY,
  name VARCHAR(200) NOT NULL,
  description TEXT,
  survey_id VARCHAR(100),                -- 关联问卷ID
  status VARCHAR(20) DEFAULT 'draft',   -- draft/active/paused/completed
  total_samples INTEGER DEFAULT 0,       -- 目标总量
  selected_dimensions JSONB,              -- 选中的维度列表
  quotas JSONB,                          -- 配额详情
  red_packet_amount INTEGER,             -- 红包金额（分）
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

-- 答卷记录表
CREATE TABLE survey_responses (
  id SERIAL PRIMARY KEY,
  project_id INTEGER REFERENCES projects(id),
  openid VARCHAR(64) NOT NULL,
  survey_submit_id VARCHAR(100),         -- 问卷平台提交ID
  answers JSONB,                         -- 答卷内容
  is_red_packet_sent BOOLEAN DEFAULT FALSE,
  red_packet_sent_at TIMESTAMP,
  submit_time TIMESTAMP NOT NULL,
  created_at TIMESTAMP DEFAULT NOW()
);

-- 配额进度表（按维度统计）
CREATE TABLE quota_progress (
  id SERIAL PRIMARY KEY,
  project_id INTEGER REFERENCES projects(id),
  dimension_key VARCHAR(50),
  tag_name VARCHAR(50),
  current_count INTEGER DEFAULT 0,
  target_count INTEGER DEFAULT 0,
  updated_at TIMESTAMP DEFAULT NOW(),
  UNIQUE(project_id, dimension_key, tag_name)
);
```

### 4.2 索引建议

```sql
-- 用户表索引
CREATE INDEX idx_user_openid ON user_profiles(openid);
CREATE INDEX idx_user_gender ON user_profiles(gender);
CREATE INDEX idx_user_age ON user_profiles(age_range);
CREATE INDEX idx_user_region ON user_profiles(region);

-- 答卷表索引
CREATE INDEX idx_response_openid ON survey_responses(openid);
CREATE INDEX idx_response_project ON survey_responses(project_id);
CREATE INDEX idx_response_submit_time ON survey_responses(submit_time);
```

## 七、非功能性需求

### 7.1 性能要求

| 指标 | 要求 |
|------|------|
| 并发用户 | 支持 1000+ 同时在线 |
| 答卷处理 | Webhook 响应 < 200ms |
| 红包发放 | 成功率 > 99.9% |

### 7.2 安全要求

- Webhook 签名校验（SHA256）
- 微信支付调用需双向证书认证
- 用户 openid 脱敏存储
- 接口需登录态验证

### 7.3 部署建议

| 环境 | 方案 |
|------|------|
| 开发测试 | Docker Compose（PostgreSQL + App） |
| 生产 | 腾讯云 Lighthouse + PostgreSQL |
