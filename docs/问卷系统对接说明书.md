# 问卷系统对接说明书

**版本**：V1.0
**日期**：2026-03-31

---

## 一、需求概述

真人样本库需要从问卷系统获取用户答题数据，核心对接需求：

| 需求 | 说明 | 优先级 |
|------|------|--------|
| **自定义参数传递** | 答题链接中嵌入 openid，答题时自动携带 | P0 |
| **Webhook 数据推送** | 用户提交答卷后，主动推送到真人样本库接口 | P0 |

真人样本库内部业务逻辑（问卷系统无需关注）：
- 用户画像管理与抽样筛选
- 配额配置与目标追踪
- 红包发放与状态回写

## 二、自定义参数功能

### 2.1 功能描述

在问卷链接中嵌入自定义参数，用户点击答题时，问卷系统自动将参数回传到答卷数据中。

**⚠️ 重要说明**：
腾讯问卷商业版仅支持 **1个自定义参数**，因此 `openid` 和 `project_id` 需要合并传递。

### 2.2 必填参数

| 参数名 | 说明 | 格式要求 |
|--------|------|----------|
| `__DATA__` | 合并参数（openid + project_id） | 格式：`{openid}_P_{project_id}` |

**合并规则**：
- 拼接符：`_P_`（分隔 openid 和 project_id）
- 示例：`oXXXXXX_P_PROJ_001`
- 真人样本库接收后解析拆分

**示例**：

真人样本库构建的问卷链接格式：
```
https://survey.example.com/s/12345?__DATA__=oXXXXXX_P_PROJ_001
```

用户点击后，问卷系统需要在答卷数据中包含：
- `openid`: `oXXXXXX`
- `project_id`: `PROJ_001`

**说明**：`__DATA__` 为合并后的单参数，问卷系统需要在用户访问时自动替换为真实值，并在答卷数据中回传 `openid` 和 `project_id` 两个字段。

1. **链接生成支持参数嵌入**
   - 在问卷后台配置自定义参数字段
   - 在发送问卷链接前，将真实 openid 替换到链接中

2. **参数自动携带**
   - 用户无需手动填写 openid
   - 提交答卷时，问卷系统自动将 openid 写入答卷数据

## 三、Webhook 数据推送

### 3.1 功能描述

用户提交答卷后，问卷系统自动将数据 POST 到真人样本库指定接口。

### 3.2 配置项

| 配置项 | 说明 |
|--------|------|
| Webhook URL | 真人样本库接收数据的接口地址 |
| 签名密钥 | 用于真人样本库校验请求来源 |
| 推送时机 | 实时推送（推荐） |

### 3.3 数据格式

**POST 请求格式**：

```
POST {webhook_url}
Content-Type: application/json
X-Signature: {签名}
```

**请求 Body 示例**：

```json
{
  "event": "survey.submit",
  "timestamp": 1743427200,
  "data": {
    "survey_id": "SURVEY_001",
    "submit_id": "SUB_123456",
    "custom_args": {
      "data": "oXXXXXX_P_PROJ_001"
    },
    "answers": [
      {
        "question_id": "Q1",
        "question_type": "single",
        "answer": "A"
      },
      {
        "question_id": "Q2",
        "question_type": "multi",
        "answer": ["B", "C"]
      }
    ],
    "submit_time": "2026-03-31 16:42:00"
  }
}
```

### 3.4 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `event` | string | 事件类型，`survey.submit` 表示提交答卷 |
| `timestamp` | number | Unix 时间戳 |
| `data.survey_id` | string | 问卷 ID |
| `data.submit_id` | string | 提交记录 ID（唯一） |
| `data.custom_args` | object | **自定义参数** |
| `data.custom_args.data` | string | 合并参数，格式 `openid_P_project_id`，真人样本库接收后解析 |
| `data.answers` | array | 用户答题内容 |
| `data.submit_time` | string | 提交时间，格式 `YYYY-MM-DD HH:mm:ss` |

### 3.5 签名校验（建议）

为防止伪造请求，建议真人样本库根据签名密钥验证请求来源。

**签名算法**（示例）：
```
signature = SHA256(timestamp + body + secret_key)
```

## 四、数据流转图

```
┌──────────────────────────────────────────────────────────────────┐
│                         完整数据流转                               │
└──────────────────────────────────────────────────────────────────┘

① 真人样本库
   ├── 根据用户画像筛选符合配额的用户
   ├── 生成问卷链接（__DATA__=openid_P_project_id）
   └── 通过模板消息/其他渠道推送给用户

② 用户
   └── 点击链接，进入问卷答题页（__DATA__已自动注入）

③ 问卷系统
   └── 用户提交答卷 → 自动携带 custom_args.data（oXXXXXX_P_PROJ_001）

④ Webhook 推送
   └── POST 到真人样本库接口：{ custom_args: { data: "oXXXXXX_P_PROJ_001" }, answers: [...] }

⑤ 真人样本库
   ├── 解析 data 字段得到 openid 和 project_id
   ├── 根据 openid 匹配用户
   ├── 判断是否符合项目配额
   └── 符合则发放红包
```

## 六、注意事项

### 6.1 openid 必填

`custom_args.openid` 是真人样本库发放红包和关联用户的核心字段，**必须确保正确传递**。

### 6.2 实时性

Webhook 推送建议实时进行，用户提交答卷后立即推送，以便真人样本库及时发放红包。

### 6.3 重试机制

建议问卷系统在推送失败时支持重试（最多3次），避免因网络问题丢单。

### 6.4 数据安全

- openid 属于用户隐私数据，建议 HTTPS 传输
- 真人样本库仅用于红包发放和用户关联，不会对外泄露
